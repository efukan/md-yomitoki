# 外部更新と変更の表示

外部で書き換えられたファイルを読み直し、どこが変わったかを見せる仕組み。サイドバーの「変更」欄は [app.md](app.md)。

## ファイル監視と読み込み

- `O_EVTONLY` で開いたファイルを vnode の `DispatchSource`（write/extend/delete/rename）で監視する。delete/rename を受けたら監視を外して同じパスを最大約1秒リトライして開き直す（アトミック保存対応）。見つからなければバナーを出し、表示内容は残す（読み込めない理由が他にあればそれを出す）。
- イベント後は 150ms デバウンスしてから読み込む。空ファイルを読んだら1回だけ再試行する（truncate→write の途中を拾わないため）。**最後に読み書きした内容と同一なら何もしない**（自分の保存による自己発火防止を兼ねる）。
- 読み込みは `Data(regularFileAt:limit:)`：通常のファイルだけを 10MB（Finder と同じ 1000 単位）まで（FIFO で固まったり、/dev/zero へのシンボリックリンクでメモリを使い果たしたりしないよう、`O_NONBLOCK` で開いて fstat で確かめる）。読まない理由は `FileReadRefusal`（通常のファイルでない・大きすぎる〈実際の大きさと上限〉・文字コードを判別できない）で、開いた時は「読み込めませんでした」の説明に、外部更新の時はバナーに出す（表示は最後に読んだ内容のまま）。UTF-8 →だめなら Shift_JIS。BOM はバイト列で判定する（Foundation の UTF-8 デコードは BOM を黙って取り除くため）。内部では改行を LF に正規化し、保存時に元の文字コード・改行コード・BOM（`FileFormat`）で書き戻す。

## ベースラインと差分

- S0＝ベースライン（ファイルを開いた時／「確認済み」を押した時。保存した写しがあれば、その内容）、S_prev＝直前の外部更新が来る前、S_now＝現在。
- 未確認の変更＝diff(S0, S_now)（淡い色、累積するので消えない）、最新の更新＝diff(S_prev, S_now)（濃い色）。
- 自分で編集・保存した内容も「確認済み以降の変更」として表示する（3-way差分はしない）。
- S0 の写しを、開いているタブの文書の分だけ保存する（`BaselineStore`：Application Support の `<Bundle ID>/Baselines/`、パスの SHA-256 を名前にして本文の内部表現＝LF のまま）。タブを復元しても未確認の変更の印が消えないようにするため。開いた時に写しがあれば S0 にして今の内容と比べるので、閉じている間の書き換えにも淡い色の印が付く（最新の更新には含めない）。無ければ開いた時点の内容を保存し、「確認済み」でも保存し直す。
  - 写しはタブの記録（`OpenFilesSession`、[app.md](app.md)）に合わせて残す：記録し直すたびに、記録に無い文書の写しを消す。タブを閉じれば消え、全部閉じた時は記録が残るので写しも残る（次に Dock のクリックや起動で開き直すと続きから）。起動した時は開き直さなかった文書の分を消す（復元をオフにしていれば次回は開いた時点が基準。記録が無くなった写しも残り続けない）。
  - 最近開いたファイルの履歴として残す案はやめた（開いていない文書の写しが増え続けるため）。閉じたタブを後日開き直した時は開いた時点が基準になる。
  - 1MB（Finder と同じ 1000 単位。UTF-8 のバイト数）を超える基準は保存せず、開いた時点を基準にする。「確認済み」の時に超えていたら前の写しも消す（残すと、確認した変更が次回また出る）。
  - 読み書きと掃除は1本の直列キューで、頼んだ順に行う（メインスレッドの外。閉じてすぐ開き直しても順序が入れ替わらないように）。開く時は読み終えてから最初の描画を作る（印の無い本文を一瞬見せないように）。終了する時だけ書き終わるのを待つ。
  - ステータスバーの「外部で N回更新」は保存しない。閉じている間の回数は数えられず、保存しても一部だけの数になるので、開いてからアプリが見た回数のままにする（復元の直後は印があっても回数は出ない）。
- 比較の基準（`BaselineSource`）はツールバーのメニューで「開いた時点・確認済みの時点」と「git HEAD」を切り替える（`Git.swift`：`git -C <dir> show HEAD:./<name>` をメインスレッド外で実行）。git HEAD の基準は外部更新のたびに読み直す。「確認済み」はどちらの基準でも今の内容を新しい基準にする（git HEAD を選んでいた場合は通常の基準に戻る）。最後に選んだ基準は `AppSettings.compareWithGitHead` で次に開くファイルへ引き継ぐ（git 管理外なら黙って通常の基準）。
- 行単位の差分は Swift の `difference(from:)`。JS は `data-sourcepos` の範囲と変更行が重なる要素に `.chg` / `.chg-latest`、削除位置の直後（末尾なら直前）の要素に `.del-before` / `.del-after` を付ける（クラス自体には見た目を付けない。赤線は `#gutter` 層に引く。要素の影で描くと、移動した時に光らせる枠の角の丸みに沿って端が曲がったため）。エディタは本文に重ねた `EditorMarksView` に同じ印を描き、最新の更新だけ一時属性で淡く塗る。
- 差分は共通の行で区切った「かたまり」単位で数え、消えた行（`LineChanges.removed`：削除の位置か書き換えた範囲の先頭行 → 行数と本文。200行まで）も持つ。間に空行しか無い削除は1つにまとめる（見出しと本文を消すと間の空行だけが残り、削除が2つに分かれて見えるため）。

- 文字単位の差分（`RemovedLines.inlineDiff`・`LineDiff.inlineDiff`）：行の差分を置き換えず、線・⌘J・「変更」欄・付箋の追従は行の差分だけで動く。書き換えのかたまりの前後を書記素単位で比べた結果は吹き出しの強調にだけ使う（日本語の段落は1行が長く、行単位では1文字の直しでも段落全体を見比べることになるため）。吹き出しは Markdown の原文を出すので、画面上の文字との対応は要らない。本文側では強調しない（DOM の差分更新・検索の強調・最新の更新の塗りとぶつかるため）。
  - **吹き出しを開く時に、そのかたまりの分だけ計算する**（メインスレッドの外で）。行の差分を作る時は書き換えた後の行（`RemovedLines.replacement`）を持っておくだけ。プレビューは JS が `inlineDiffs` で頼み、返事が来てから出す（結果は次に印が変わるまで覚える。返事を待つ間にマウスが離れたら捨てる）。
  - 試してやめたこと：描画のたびに全部のかたまりを計算し、文書全体の手間に上限を設けた。最悪の場合を基準にすると、普通の推敲でも上限に届いた（250 字の段落 30 個を 3 か所ずつ直すと先頭の 16 個、400 字の段落 30 個を 4 か所ずつ直すと先頭の 6 個しか強調されず、実際の計算は数 ms だった）。文書の後ろの段落ほど強調されず、理由も分からないのでやめた。
  - かたまり全体を1つの文字列として比べる（行数が変わる書き換えでも行の対応を決めなくてよい）。前後の共通部分を除いてから比べる。足しただけ・消しただけは比べるまでもない。
  - 変わった所にはさまれた共通のかたまりは、両隣の変更より長くなければ変更に含める（「の」「は」だけの一致で細切れにしない）。両隣とも足しただけ・消しただけなら含めない（`重要` → `**重要**` で「重要」を塗らない）。
  - 比べないのは、共通の文字が短い方の 5 割に満たないもの（細切れになるだけ）、前後の共通部分を除いた範囲が片側 1000 字を超えるもの（全く違う文字列の比較は文字数の2乗で重くなり、片側 1000 字で Debug ビルド 約 0.3 秒かかった）、変更前の内容を省略したもの（200 行超）。その時は変更前の内容に「変更が大きいため、文字ごとには比べていません」と添える（強調されない理由が分かるように）。
  - 片側が 300 字を超える時は、80 字を超える共通部分の間を「…」で省く（吹き出しに変わった所が収まるように。エディタの吹き出しはスクロールして変わった所を出す手段が無い）。省いた時は変更前の全文をコピーできない。

## 変更ごとの操作

- 吹き出しの各かたまりの見出しに「戻す」「確認済み」のボタンを置く（長いと内容がスクロールするので内容の上。エディタも同じ）。サイドバーの「変更」欄は右クリックのメニューから（一覧は移動に使うので、押し間違えないよう行にボタンは出さない）。かたまりは `LineHunk.line`（`changed` の先頭行か `deletedBefore`）で指す。
- 戻す（`DocumentModel.revertChange`・`LineDiff.reverting`）：今の本文のそのかたまりを基準の内容に置き換える。基準から作り直すので、吹き出しで 200 行までに省略したかたまりも全部戻る。保存はチェックボックスと同じ `replaceText`（未保存の編集が無ければすぐ保存、あれば本文だけ変えて未保存のまま、⌘Z で戻せる）。確認は出さない（⌘Z で戻せるため）。
  - すぐ保存する時は、その前にファイルが最後に読んだ内容のままか確かめ、違えば戻さずに読み直して知らせる（AI が書いた直後は監視の 150ms のデバウンスの間、表示より新しい内容がディスクにある。そのまま保存するとその内容が消える）。
  - 文字数が変わってもエディタの取り消しの履歴は消さない（`applyWithoutUndo`）。文書側の取り消しも同じ履歴に積むので後ろから順に戻り、入力の取り消しの位置はずれない。
- 確認済み（`DocumentModel.acceptChange`・`LineDiff.accepting`）：基準のそのかたまりだけを今の内容にして写しも保存する。本文は変えない。最後の1か所なら全体の「確認済み」と同じ処理にする（更新の回数も数え直す）。
  - 最新の更新の差分は保存していないので、差分を取り直さず、そのかたまりに重なる印だけを除く（`LineChanges.excluding`）。
  - git HEAD と比較していた時は、HEAD にそのかたまりを当てたものを通常の基準にする（全体の「確認済み」と同じく通常の基準に移る。残りの差分はそのまま）。
- 「確認済み」（全体も1か所も）は ⌘Z で取り消せる（押し間違えると前の基準が写しごと無くなり、変更の印を出し直せないため）。基準・比較の基準の種類・更新の回数・最新の更新を覚えて（`ReviewState`）ウィンドウの取り消しの履歴に積み、戻す時は写しも保存し直す。本文は変えないのでエディタの入力の取り消しとはぶつからない。外部更新が来ると履歴ごと消え、アプリを終了しても消えるので、押し間違いの直後を救うためのもの（過去の基準をさかのぼるものではない）。基準が変わらない時は履歴に積まない。
- 行番号でかたまりを指すので、古い印のまま別のかたまりを操作しないようにする：描き直しを待っている間（`renderedText` が今の本文と違う）とエディタが今の本文と違う間（IME の変換中）はビープで断り、計算の間に本文や基準が変わったら捨てる。プレビューの吹き出しは印を置き直す時に、エディタの吹き出しは印が変わった時に閉じる。
- 差分の組み立ては `LineDiff.hunks` の1か所にまとめ、`changes` も戻す・確認済みもここから作る（印の行番号とかたまりの対応がずれないように）。

## 変更への移動

- `⌘J`（次）／`⇧⌘J`（前）：⌘J は更新後の最初の1回は最新の変更の先頭へ、以降は現在位置から文書順に巡回する。⇧⌘J は現在位置より手前へ逆順に巡回する（端まで行ったら反対の端へ回る。選び方は `LineChanges.nextJumpLine` / `previousJumpLine`）。確認済みボタンで S0＝S_prev＝S_now にそろえる。
- 行から要素を探す（`elementForLine`）ときは、開始行がその行以下で一番後ろの要素を全部の中から選ぶ。脚注は HTML の末尾にまとめて出て文書順でも行番号が戻るので、順に見て途中で打ち切ると、脚注より後の行（末尾への追記など）が文書の前の方へ飛んでしまう。

## 変更の印

- プレビューの変更の印は控えめにする（本文は最新の更新だけごく淡く塗る。削除の位置は本文の幅で 2px の赤線、左に赤い三角、右端（列の右の余白）に赤い丸い「−行数」の印。三角と印は赤線の中心にそろえ、「−」は文字だと高さがずれるので図形で描く）。色はオレンジ1系統で、濃さで新しさを表す。
  - 本文の列の左 6px に 3px の縦線（未確認の変更は淡い、最新の更新は濃い。縦に接する要素は1本にまとめ、最新を上に重ねる）。削除の位置には赤い小さな三角。どちらも `#gutter` 層に置く（当たり判定は線の左右 5px）。
  - 線・三角・「−行数」にマウスを載せるとすぐ吹き出しで、変更前の内容（追加だけなら「変更前の内容はありません」）・削除された行を見せる（「−行数」からは吹き出しの右端を印にそろえる）。書き換えは「変更前」「変更後」を並べて、消えた文字を赤、入った文字をオレンジで塗る（1本の線に複数のかたまりがあれば、組の間に線を引く）。文字は本文と同じフォントにする（等幅だと日本語が太く見えた）。エディタの吹き出しは背景を不透明の淡い灰色にする（既定は透けて後ろの文字が重なり、本文と同じ白だと境目が無くなって後ろの行が消えたように見える）。吹き出しへマウスを移しても消えないので文字を選べる。
  - 付箋のホバー印は、本文のすぐ左（線の当たり判定）では出さない。
  - エディタも同じ印（`EditorMarksView`：本文に重ねた子ビュー。クリックは素通し。見えている範囲の分だけレイアウトから位置を求めて描く。行の高さの倍率の分の余白は文字の上に入るので、線と付箋は行の矩形ではなく文字の位置にそろえ、削除の赤線は文字の間の余白の中央に引く）。吹き出しは NSPopover（SwiftUI の `RemovedLinesView`）で、マウスが印か吹き出しの上にある間は出しておく（200ms ごとに確かめる）。
- プレビューの右端のルーラー（`#ruler`、当たり判定 10px・印は 3px の1列）：文書全体を画面の高さに縮めて、変更と削除の位置を並べる（検索中だけ一致の位置を上に重ねる。付箋はサイドバーにあるので出さない）。印の近く（6px 以内）をクリックするとそこへ移動する。エディタには出さない（正確な位置を出すには文書全体のレイアウトが要り、編集のたびに重くなるため）。

## 最終更新の表示

- ステータスバーの左に最終更新（ファイルの更新日時。開いた時・外部更新・自分の保存で読み直す）を「たった今／N分前／日時（1 時間以上前）」（`UpdateTime`）で出し、15 秒ごとに表示を進める。1 分以内の更新はオレンジ（AI がまだ書いているかもしれない）。開いてから（確認済みにしてから）外部で更新された回数も「外部で N回更新」と出す。マウスを載せると正確な日時。
